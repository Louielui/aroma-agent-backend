# Capability Gap Resolution v1

Update: the later [development handoff slice](CAPABILITY-GAP-DEVELOPMENT-HANDOFF-V1.md)
registers a fixed 7shifts reader profile with fresh approval for old pending tasks.
The original slice below describes its earlier scope; live 7shifts connection
acceptance remains incomplete.

The intake reports a host-judged capability/evidence gap rather than an empty-turn
failure. A saved proposal retains the original Owner request and required facts.
The chat card shows the cause that is established, solution steps, acceptance,
impact, unverified risk, registered scope and actual handoff stage. English and
Chinese share the same gap states and approval rules.

## Connected

- Judged goal + actual read state → structured gap. Unmapped read, registry-confirmed
  unimplemented function, turn authorisation, failed source and failed verification
  remain distinct. No inferred external endpoint, scope or connector inventory.
- Durable gap proposal + original request, linked from the saved conversation.
- Owner confirmation binds one displayed proposal, revision, conversation and fixed
  scope, expires after 24 hours and is consumed once. Browser history, extra fields,
  source comments and model-generated paths cannot grant scope.
- Approval saves a development task. The registered Context profile can enter the
  existing committed-source planner. The resulting plan still needs its existing
  coding consent; adoption remains separately approved. No new development profile.
- Unknown handoff outcomes never automatically replay. Reloading reads the saved
  receipt and existing child job. Missing outcome stays unconfirmed.
- After matching reviewed development and verified loaded adoption, an explicit
  read-only continuation rechecks the saved original request. Its request identity
  is persisted before the call and retries cannot duplicate a paid request.

## Partial / unconnected

7shifts, QBO and other unregistered external development scopes produce an approved
task in `awaiting_scope_registration`. They are not dispatched to an arbitrary
worker and are not reported as connected. Registering new fixed connector scopes,
credential setup, external permission approval and business writes are outside this
slice. Restoring a denied read does not mean implementing a new connector.

The first 7shifts acceptance is gap → concrete proposal → approval → saved handoff,
with original clock-out request intact and no payroll write. It does **not** establish
that 7shifts time-punch data is now accessible or that punches can be approved.
The continuation/adoption branch is covered with controlled workflow evidence; it
must not be reported as a completed live 7shifts integration.

No extra model call is needed to prepare or approve the gap proposal. Only the
explicit registered development-planning handoff and verified read-only continuation
use the existing subscription model selected for that request. No background retry,
new privileges, API fallback or automatic production adoption is added.

Validation: intake regression, service state/authority/concurrency tests, actual
HTTP route integration, durable restart, UI behavior, existing task planner,
conversation, governance, bilingual and architecture checks. Delivery evidence
records the loaded boot commit and real Owner-facing 7shifts gap response.
