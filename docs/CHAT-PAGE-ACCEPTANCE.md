# Chat page task profile

The Owner can plan and register changes to the existing chat HTML, JavaScript
and CSS. A task selects one profile only. Unselected chat assets, translations,
sidebar assets, page assembly and browser harness are committed read-only input.
No arbitrary paths, new files, dependencies, remote operations or business writes
are added by this profile.

Protected drafting, independent review, task registration, coding and adoption
retain their separate one-use Owner approvals. A red baseline is required before
coding. The generated tests have a fixed count; four host-defined browser tests
are added automatically and cannot be replaced by the coding worker.

The browser runs in the existing offline Windows Sandbox, with a fresh Edge
profile in disposable guest scratch. It never uses an Owner browser or account.
Requests are intercepted and fulfilled with synthetic responses; unexpected
requests fail acceptance. Both languages and desktop/mobile widths exercise
startup, labels, Sol/Medium defaults, five reasoning choices, keyboard input,
model menu and layout. One scenario returns failed background reads.

Screenshots and browser metadata survive guest shutdown in the bounded output
directory. The host verifies names, cardinality, dimensions, sizes and hashes.
Owner-authenticated work history and chat cards link to the retained images.
Image retrieval rechecks the original evidence and screenshot digests. These are
synthetic-data browser observations, not proof that external integrations work,
and visual review remains the Owner's decision.

Adoption requires four complete proofs in the accepted receipt and a fresh test
run before applying the sealed patch. Source, dependencies and protected tests
must remain unchanged. Rollback restores the measured original behavior through
its existing independent approval and version verification. Administrator reload
protection remains in effect.
