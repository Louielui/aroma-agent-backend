# Investigation gap recovery v1

This delivery extends the existing read-only investigation, without management
dispatch, new credentials, scheduling or new permissions.

## Connected path

- Judged typed evidence needs map through a closed capability equivalence table.
  An unavailable development_record can select authorised GitHub code evidence.
  Documents, correspondence and events use their respective authorised readers.
- One round, at most two additional sources; attempted sources are never repeated.
  Empty/unavailable required external reads and unmapped facts are explicit gaps.
- Work-failure GitHub continuation reads one commit at the failed task's exact
  source SHA in the configured repository. Missing SHA/repository fails closed;
  there is no recent-PR fallback. This verifies source context, not a repair.
- Structured workRunId/taskRunId links join records; titles and timestamps do not.
  Candidate test success, completed adoption, loaded revision and current file
  hashes remain separate evidence. Duplicate identities are ambiguous.
- A later completed adoption retry for the exact same workRunId, passing complete
  tests, matching commit/loaded revision and current candidate file hashes may
  confirm recovery of a source_dirty/source_changed adoption prerequisite only.
  It does not establish a product regression fixed. Unknown/contradictory/missing
  evidence remains explicit in bilingual reports and saved investigation receipts.

## Validation

Router/intake tests exercise Chinese and English through the same pipeline,
unmapped development evidence, exact revision arguments, source limits, denied
sources, no duplicate reads, missing revisions and no management tasks. Work
tests reject unrelated later successes, shared task IDs alone, rollback, partial
tests, duplicate records, changed files and loaded-revision mismatch. Cross-domain
typed needs are exercised without a fixed Memory-to-Mail ordering.

## Remaining boundaries

Development-record integration itself remains unavailable. A remote source may
not contain a local-only commit. Live cross-source discovery is bounded and does
not guarantee a repair record exists. Same-failure regression proof in the loaded
application, provider billing and complete external job inventory remain gaps.
Architecture status remains partial; live delivery receipts record measured
outcomes separately from fixture validation.
