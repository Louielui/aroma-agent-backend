# Consent-bound browser operator

The Owner requested real pointer movement and screen clicks, with independent
browser topics, and selected entering the 7shifts employee page and reading its
data as the first live acceptance task. This addition is separate from the old
inert Computer Operator canary. Its absolute prohibitions remain unchanged.
The new consented job participates as a computer lane in the existing execution
matrix; an active peer lane refuses input rather than changing launcher flags.

The side panel binds the job to its own active, focused Chrome tab and window.
The native Chrome child runs in the interactive session; Backend never sends
desktop input from LocalService. A fixed, hash-pinned C# helper independently
verifies the foreground Chrome process, address-bar URL, matching UIA Document,
viewport geometry and unchanged pixels. Unknown or ambiguous URL/Document
exposure refuses capture/input; there is no coordinate or URL guess fallback.
Chrome's scheme-omitted address display is accepted for the exact owned HTTP
fixture only. The independent Document URL still requires its complete fixture
URL; other HTTP destinations, ports, queries, fragments and aliases do not gain
this address-display exception.
Window movement, resizing, focus or frame changes refuse the next native action.

The same captured central subscription brain receives one ephemeral PNG and
bounded visible text per step. Page data and prior observations are untrusted.
The model returns a closed action. Live 7shifts clicks can only select an observed,
unobscured company Employee/Employee list link; free clicks, other routes and
typing are refused. Move and scroll are supported in the approved viewport.
The owned local fixture additionally admits its button/input, the exact synthetic
text `Imagine test`, and Enter in that fixture input. No shell, clipboard,
arbitrary app, browser chrome, credentials, uploads or business writes exist.

**Live sites are closed in this release.** The default service refuses a 7shifts
start with `operation_native_acceptance_required` before any audit/provider/native
dispatch. Only the owned fixture can start in the actual app composition.
Tests explicitly inject the later live profile to exercise its route guard.
Activation is a separate exact-source change after positive native acceptance;
neither a client field nor an environment flag can unlock it today.

Backend consumes a five-second input ticket before native execution, once only.
A failed or unknown native return never retries. Twelve steps and ten minutes
bound a job. Stop aborts inference and the exact tracked helper process; a native
SendInput batch already handed to Windows cannot be recalled. Closing/moving or
switching the source tab stops its job. Pointer movement by the Owner and Escape
are checked during native execution; the side-panel Stop also works during
inference. Backend restart interrupts in-memory jobs; none resumes automatically.

Raw frames and page text are neither saved nor returned to the panel. The local
audit records job ID, stages, requested/actual model, step and kind. Saved answers
stay in the current topic only. Operator answer restore performs no inference or
native actions. This initial operator does not restore an unfinished job, open
employee editing views, search arbitrary sites, act in Drive, or provide general
desktop control. It is not a claim of GPT feature parity.

Chrome permissions and ID are unchanged. Native Host does gain scoped image
capture and real input, so its exact source is an Owner-bound permission scope,
not a read-only update. Installer prepares a new immutable helper/extension pair,
pins all executable blobs and compiled helper, retains the previous registration
and rollback package, and changes only the existing per-user Native Host key.

## Evidence boundary

Node service/broker tests exercise binding, cancellation, no replay, uncertain
input, matrix conflict and frame/window refusal. Headless Edge tests exercise the
real panel's consent, stop, text-safe output and answer restore with synthetic
responses. Windows tests compile the actual helper and refuse unauthorized URLs
before any desktop observation/input. These are not a positive native input test.
Live acceptance must first prove nonzero trusted move, click, type, Enter and
scroll counters on `/browser-operator-fixture`, then prove stopping prevents a
later step. Only then attempt the explicitly authorized 7shifts navigation/read.
An installed source revision alone never counts as native or 7shifts acceptance.

Owner acceptance on 2026-10-14 verified Chrome loaded the `28ef758` extension.
A narrow viewport first refused a clipped fixture input. After maximizing the
window, the native host refused the fixture's scheme-omitted address display
before capture or input. Compiled-predicate regression reproduces that refusal
and exercises the bounded display correction and unchanged Document check.
Positive trusted input and Stop acceptance remain pending after package update.
