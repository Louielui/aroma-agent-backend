# Registered UI design and actual-pixel review

The Owner wants a calm chat-first interface and visible real work progress. UI planning, protected acceptance drafting and isolated coding now receive one host-owned skill from `skills/xiangxiang-ui-design/`. Its normalized content hash is retained with new registered UI work. It cannot grant editable files, credentials, tool access or adoption authority.

Supported profiles remain the existing two sidebar assets or the existing chat assets. Other screens and arbitrary projects are unconnected. The design system specifies hierarchy, spacing, menu behavior, existing branding/tokens, conversation space, responsive controls and collapsed technical evidence. Owner refinements override visual defaults within the registered scope.

After an independent correctness pass, new UI candidates receive a separate actual-pixel review. The host reads all four immutable offline Edge screenshot proofs (Chinese/English, desktop/mobile), checks the evidence and PNG hashes, and sends the image bytes through the existing ChatGPT subscription connection to GPT-6.1 Sol at Medium. Tools, shell, MCP, filesystem reading and hooks stay disabled. Images and their page text are evidence, never instructions. Available credits follow existing Owner policy; there is no paid API fallback or new dependency.

Strict structured verdicts must identify all four views. A pass requires no findings; a rejection requires concrete findings. Missing images, wrong model/billing, incomplete responses or altered evidence stop the workflow. Before completing or adopting new UI work, the visual receipt must match the exact patch, screenshot hashes and isolated design receipt. Correctness rejection does not call the visual model. Visual rejection preserves evidence and stops for changes; automatic visual repair is not connected. Old archived receipts are not replayed or silently upgraded.

Chat and the work page offer collapsed screenshot previews and a concise visual summary. Existing live work stages now include design guidance and screenshot review. They describe recorded events, not private model reasoning or invented execution. Functional browser checks and aesthetic review remain separate; a model verdict is not a guarantee of every state or the Owner's taste.

This delivery also refines the homepage: compact grouped top navigation, floating menus, one brand, independently scrolling history, keyboard dismissal, an accessible mobile header, and a single-row mobile composer with the send action at the right. All destination IDs and handlers, conversation history, settings, model choices and the five reasoning levels with Medium default are preserved. Production business data and the paused memory acceptance automation remain unchanged.

Delivery evidence is stored in the workspace `outputs/ui-design-browser.json`, `ui-design-visual.json`, `ui-design-suite.json` and `ui-design-deployment.json`. Actual screenshot feedback prompted mobile layout and control-size revisions before the final review. Functional acceptance is not reported as aesthetic approval; only the recorded actual model verdict can establish the latter.
