## Candidate behavior

- An acknowledgement without a current interface-planning receipt returns to the
  existing understanding path with the original server history. A present invalid
  receipt still cannot start planning. Same-chat valid receipts, source revision,
  expiry, request identity and independent execution authorization remain enforced.
- A contextual confirmation does not attach the generic path-entry form over the
  answer. Explicit current-message file changes and registered workflows keep
  their existing routes. Failed server-history reads return a typed unavailable
  state, not an interface question.
- Recommendations use one guarded main body rather than another leading executive
  statement. Existing supplementary uncertainty/change conditions remain available
  through the existing advice-basis disclosure. Blocked judgments, action cards,
  read/evidence guards and operational investigations retain their boundaries.
- The existing answer prompt requests a brief conclusion and up to three compact
  points by default; explicit detailed requests take precedence. Material risks,
  conditions and approval requirements belong in the main answer. This is guidance,
  not proof that an unseen model response will obey a length limit.
- Plain long paragraphs receive lossless two-sentence spacing. Text is split only
  when joining every segment reproduces the entire source. Markup/code/lists stay
  intact, and no body or warning is automatically truncated or hidden. Supplementary
  basis and source evidence continue using existing disclosures. The common message
  and composer measure is 680 px with responsive wrapping and more paragraph space.
- Empty read sections contribute no orphan heading. A legitimate source title with
  no verified numeric facts is not invented into a metric or silently deleted.
- A source-rendered ordinary answer archives a neutral evidence-check receipt rather
  than an obsolete unverified draft or newly copied third-party rows. The conversation
  retains the full visible answer. This privacy-preserving receipt is deliberately
  distinct from that full answer; it is not claimed to be byte-identical.
- Whole-request stable definitions and colon-delimited supplied-text transformations
  can use the existing one-answer path after a topic change. History still enters the
  main prompt. Referential, current/private, compound or attached-context requests
  remain in the full pipeline. Existing fast-path output validation refuses actions
  and new reads. No model/effort, memory setting, credentials or existing allowance
  was changed; the separate proposed profile below remains inert.

## Verification and limits

The actual saved acknowledgement is replayed through the original and candidate
HTTP routers using isolated data and explicitly substituted understanding output.
The original calls understanding zero times and shows the interface question;
the candidate calls it once, retains message roles/order/content and returns no
planning job, execution or masking file form. This proves routing, not a new
model's semantic accuracy. Actual saved long output is separately rendered in the
candidate browser, comparing every word and the visible desktop/mobile layout.

Focused failures precede the corresponding changes. Tests cover receipt expiry,
cross-origin and extra-field refusal, valid planning/dedup, prompt history,
single-call topic changes, untouched read/permission gates, source archive privacy,
empty sections and lossless layout. Existing native passes remain historical
evidence on their recorded versions. Source tests, substituted replays and pixels
are not native production acceptance or a claim of general perfection or speedup.
