# Memory failure execution tracing v1

Read-only investigation links local canonical failure metadata to bounded Owner
bridge invocation receipts using all six host trace fields. Names, configured
models and neighboring timestamps cannot establish identity. Missing receipts,
unavailable sources and conflicting identities remain UNKNOWN, UNAVAILABLE and
CONTRADICTED. Provider failures/results are historical observations, not a claim
that all memory failures share a cause or that a dependency is healthy now.

Normal existing processing retains at most six safe attempt observations per
record. Index lookup failures now retain a host trace; consolidation failures
retain checkpoint and closed validation categories. The record projection returns
at most twelve samples per role, explicit omission counts and incomplete history.
No original memory text, model output, credential or raw error is included.

A later local completion requires the same canonical record, work identity,
increased attempt number and nondecreasing observation time. Changed source
identities cannot prove recovery. Completion is not remote read-back. Retry limits,
approvals, eligibility, source freshness guards and candidate validation remain
in force. No forced recovery, management write capability or new source permission
is added. Old untraced failures remain untraced; historical causes are not invented.

Acceptance covers lookup failure followed by normal completion, quote/policy
validation rejection followed by normal empty consolidation, bounded history,
safe metadata, exact invocation matching, conflicts, unavailable/missing history,
and bilingual saved investigation evidence. Runtime acceptance only reads the
existing failure population; it does not retry it.
