# Investigation Intelligence v1

The existing governed Goal Decomposer and read-only orchestration select sources
from enabled, provider-authorized operations. Memory recall does not choose sources
and an empty recall does not suppress other authorized reads. The operational
investigation now evaluates its section receipts before the answer call and saves
that evaluation alongside the existing durable progress and answer receipt.

The Owner-user subscription bridge adds a fixed authenticated metadata read. It
reads only session files whose first metadata event identifies the registered
Xiangxiang development workspace or backend checkout. It projects timestamps,
session identity, model/effort, observed task start/completion events and the latest
recorded cumulative token snapshot. Account identifiers, prompts, message bodies,
reasoning, tool output, credentials, paths and rate-limit records are not returned.
The service receives this projection; no additional LocalService directory ACL is
granted. No caller-supplied paths, commands or model executions are accepted.
Reading metadata neither occupies nor releases the model execution lane.

Enumeration is bounded to 256 directories, 3000 candidate files and 120 inspected
files. Each eligible file contributes at most 4 MiB. Large files retain a prefix
and tail with explicit incomplete-file coverage; hashes identify the exact sampled
bytes, not an entire unread file. Five recent project records are returned with
omission, malformed-line, failed-file and excluded-workspace counts. Enumeration,
sampling and omission cannot prove absence or establish current activity. A token
counter is one cumulative snapshot per session; repeated snapshots are never
summed, and forked sessions are not aggregated into an account total.

A heartbeat automation identifier found in a user message is only a declaration.
An exact match with a current automation definition produces a possible link, not
an authenticated trigger or charge cause. Current paused definitions and historical
execution are separate observations. Billing remains unconnected. Unknown actual
cost stays unknown; estimates and recorded tokens cannot become credits or money.

The deterministic evaluator labels current configuration/schedule observations,
historical execution/work, historical statements, measured cumulative tokens and
legacy estimates separately. Opposing structured lifecycle states for the same
source identity and time remain contradictions. Different dated states remain
transitions. This mechanism does not claim to detect every semantic disagreement
in natural-language history. Evidence and its gaps go to the answer model with
the existing source and scalar-fact validation. Recommendations are read-only.

The bilingual interface shows the execution/billing distinction plainly, actual
source progress and unavailable-source fallback. Technical receipts, coverage,
evaluation, hashes and records are folded. Existing saved answers and interrupted
receipts do not redispatch on duplicate, reload or restart.

Acceptance uses the Owner's credit question, plus isolated tests for missing memory,
English, unauthorized callers, cumulative snapshot deduplication, malformed and
partial coverage, workspace isolation, metadata concurrency, conflicts, lifecycle
transitions, bilingual mobile rendering and saved-result recovery. External billing,
authenticated trigger correlation, exhaustive history and a full Windows task
inventory are gaps, not completed integrations. Management actions and Email writes
remain a separate future Action Gateway phase.

When the entire required operational scope fails, the failure remains explicit and
no repeated subscription answer/read is attempted in that turn. Plans requiring
other sources retain their ordinary governed read loop. The isolated regression
reproduced five answer calls before the fix and one after; this is a potential usage
mechanism, not historical charge attribution.
