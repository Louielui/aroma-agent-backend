## Candidate change

For ordinary `recommend` turns with no source reads, corrections, authored
clarification or operational investigation, preserve the complete guarded reply
as the single main answer. Return the existing validated judgment's status,
uncertainties and change conditions as `adviceBasis`. The existing chat renderer
shows those supplementary fields in an initially closed details element, using
text nodes and bounded lists. It does not repeat the judgment statement. This
metadata is explanatory and cannot grant actions or read permissions.

Blocked judgments, chat questions, proposal fallback, source-bearing and failed
read responses retain the leading-judgment behavior. Public summaries and
operational evidence protections remain unchanged. The three-state judgment
schema, parser bounds, no-reasoning-trace contract and action approvals remain.

The judgment labels and instructions now use written Traditional Chinese. The
directive requires a complete, concise main answer including material caveats;
it forbids treating hypothetical examples as proof of frequency, time cost,
risk or comparative savings. These are semantic instructions, not sentence
matching or a keyword routing exception. No new helper call is introduced.

Supplementary basis accompanies the live response. Existing conversation history
continues to preserve the main answer; this patch does not add a memory store or
retroactively populate supplementary fields in old conversations. Raw native
packets and evidence remain in the existing acceptance audit.

## Verification and limits

Offline HTTP replay uses the retained real model answer, not a model that is
scripted to notice a new prompt marker. It checks exact reply preservation,
retained supplementary uncertainty, no work creation, and unchanged leading
judgments outside ordinary recommendations. DOM tests check a closed details
element, available uncertainty/change conditions and text-only rendering.

Full isolated tests and independent complete-commit review are required again.
An isolated browser preview can verify presentation with the retained packet;
it must be labelled offline and zero-model. Neither that replay nor a test count
proves a fresh model will follow the revised brevity instructions.

requires fresh exact-SHA scope/Hold/deployment authorization; the completed
