# Registered development worker execution evidence

The Owner bridge shares one invocation ledger with registered project-tasks,
project-runs and the fixed offline fixture. Before approved execution, the host
persists a bounded canonical run identity. Actual Codex completions and Claude
print/review calls inherit it through host-only async context. Authentication,
catalogue reads, sandbox tests and adoption do not create model receipts.

Work identity binds the canonical folder and UUID. Individual runs have new UUIDs;
reviewAgain increments the host attempt. Candidate repair and Claude formatting
retry remain model invocations within one host run, not invented scheduler runs.
No retrospective backfill, new execution routes, automatic retry or model changes.

Provider output and host completion are separate. CLI startup is only a process
dispatch witness. Unknown failure usage is retained as unknown, never zero. Raw
source, prompts, review prose, credentials and CLI cost estimates are excluded.
Codex last-turn usage remains per receipt; it is not summed as a complete work
total. Claude helper usage remains model-specific. Neither proves credit charges.

Canonical work metadata exposes matching host run identities only when the stored
record ID matches its pinned filename. Existing workCorrelation and repairChain
continue to require exact task/work links, hash-bound tests, current source
comparisons and fresh adoption/load proofs. A completed candidate is not a live
deployment. Missing sampled canonical records remain unknown.

Coverage is partial and bounded. Controlled code repair, legacy workers, website
workers, external application execution and provider billing are unconnected.
The receipt lane adds no management permissions and initiates no background work.
