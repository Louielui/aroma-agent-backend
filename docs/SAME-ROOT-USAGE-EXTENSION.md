# Same-root repository usage extension

This is an additive operation in the existing Action Gateway, Owner sealed
approval store and usage ledger. It creates neither a new task nor a new budget
root. The base development profile remains eight helpers, one turn, zero websites.
Only a validated one-time extension on that same ledger permits ten total helpers.

The original eight terminal attempts must already be present, and are bound by
their exact hash. Preparation requires an eligible failed work record, matching
root/registration, current boot source and verified shared idle state. It seals a
ten-minute single-use Owner nonce. Applying it preserves the profile, original
attempts, children, turns and history and appends an Action-store audit event.
There is one additional Sol/High coding attempt and one Sonnet/medium result-review
attempt. Each purpose can reserve once, even if it fails before sending. A coding
retry cannot use the review slot. Attempts remain conservative capacity rather
than purchased credits. The original paid-acceptance profile cannot be extended.

Unused capacity expires at most sixty minutes after preparation. Restart retains
the applied grant and all counters, but discards unclaimed in-memory tickets.
The same lock and atomic store writes protect grants and parallel reservations.
Replay, changed source/work/profile/old-attempt hashes, wrong purpose/model,
pending calls and failed persistence refuse before dispatch. Expired unused
capacity is reported separately and never refunded. No automatic reissue exists.

`scripts/repository/approveUsageExtension.cjs inspect|approve` accepts only the
reviewed candidate SHA, PR, native evidence-run UUID, existing root UUID and work
UUID. Inspect creates no grant. The explicit approval mode requires the existing
interactive Owner-terminal identity and typed exact material hash. It verifies
the real native tests and raw independent review, and that the currently running
source tree equals the reviewed tree. It therefore cannot be used to activate
unreviewed or undeployed code. It uses the existing Action Gateway and cannot
dispatch work, merge, reload, supply a shell command, import an approval or
change the approved count. No model tool or generic Bridge route is registered.

After authorized delivery and application, original same-ID recovery remains its
own source-bound sealed approval. The two fixed purpose wrappers are applied
inside that existing workflow; tests/source/failure are not regenerated or erased.
Its native sandbox and result review must still succeed before any candidate is
accepted. Existing Hold, Policy, deployment, memory-idle and P02-C boundaries stay
independent. This implementation, its offline fixtures and the Owner's usage
decision are not evidence that production has loaded or activated it.
