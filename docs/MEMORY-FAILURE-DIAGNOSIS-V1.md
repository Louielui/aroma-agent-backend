# Memory failure diagnosis v1

On-demand, Owner-gated, read-only diagnosis over the existing canonical general
memory reader. It adds no model calls, dispatch, retry, reindex or management rights.

## Connected

- Goal planning maps memory-processing diagnosis to background / memory_failures
  and the existing authorized xiangxiang_operations configuration source, in either
  Chinese or English. It is distinct from development-task failure diagnosis.
- Current active general index records and consolidation-policy-eligible sources
  share the exact canonical progress populations. Mail source-bound records remain
  excluded before projection. Only fixed safe codes, counts, attempts and times
  leave the gateway: never original text, identities or raw exception messages.
- Counts are confirmed local bookkeeping; reasons and retry classifications are
  supported recorded-state evidence. Persisted schedules do not prove execution.
- Retry states distinguish scheduled, due, limit reached (three attempts), blocked
  by existing index validation/auth rules, and incomplete/inconsistent unknown.
  Index invalid-text source-only reconciliation is an existing special path;
  blocked means no regular automatic failure retry, not proof of no reconciliation.
- Last completion/failure times are maxima among retained current records only.
  Raw-only index and empty consolidation are valid completed processing outcomes.
  They do not establish extracted facts, approved memory or remote persistence.
- Structured bilingual recommendations retain validation protections, describe
  the affected stage, and never attribute generic unavailability to Claude login,
  quota or model choice. No new background activity is started by this read.

## Not connected

Complete per-attempt history, remote persistence read-back, dependency root-cause
verification, per-record recovery and management writes. An old authorization error
does not prove the present Claude subscription route is unauthenticated. Invalid,
stale, contradictory or unavailable diagnostics remain explicit gaps.

## Acceptance

Canonical gateway with forbidden engine/write probes; safe projection conservation,
unknown reasons, incomplete/future timestamps, retry limit/blocked differences,
source-bound exclusion; live process reader, normal context route and actual intake
with bilingual questions; saved presentation/evidence and no dispatch. Loaded health
boot commit and architecture checklist must match delivery.
