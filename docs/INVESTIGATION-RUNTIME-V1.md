# Investigation runtime evidence v1

The authenticated, closed `/runtime-metadata` bridge read accepts only `{}`. It
reads one fixed root Windows task under the signed-in Owner. This avoids treating
the service identity's filtered scheduler view as absence. Query failures remain
unreadable; missing booleans and results never become false or successful zero.
Windows timestamps are converted to UTC with explicit offsets.

Backend probes observe registered mail sync, analysis and indexing, plus general
memory processing. Bridge probes observe active chat and memory completion
requests without invoking models. The mail probe does not read mailbox bodies or
enumerate semantic records. Model routing is configuration evidence, separate
from current occupancy, completed inference, historical execution and billing.
The food-recall task is deterministic and does not use an AI model.

The final Owner answer always retains a compact, receipt-bound inventory of the
registered runtime observations when the model's reviewed explanation omits
them. Each row retains its observation time and configured-vs-selected model
basis. Ambiguous duplicate rows are disclosed rather than choosing one as fact.
Rejected model claims remain rejected; saved replies include the same inventory.

Independent evidence sections are read concurrently, in stable receipt order.
They share one bridge snapshot per enquiry, retain per-source duration and each
failure, and bound loopback metadata reads to ten seconds. Structured conflicts
compare the same category and identity; dated changes remain transitions rather
than cross-role model contradictions. This does not implement semantic conflict
proof, account-wide worker inventory or provider billing attribution.

No background work is paused or rescheduled. No external write, paid API or
management action is introduced. Architecture remains partially connected.

Regression coverage includes strict scheduler results, denied reads, UTC dates,
authenticated metadata during active inference, component probes, shared source
reads, source failure isolation, current/historical grading, contradictions and
bilingual summaries. Delivery acceptance must verify the loaded backend revision,
Owner bridge reload, live Windows task and a saved real background enquiry.
