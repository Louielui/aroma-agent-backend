# Registered multi-file development v2

The Owner can select a host-registered backend task on `/project-work`. v1 single-file receipts and adopted history remain unchanged. v2 registers `context-provenance-snapshot-v2`: `src/context/contextResult.js` and `src/context/toolGateway.js`, ten immutable host-reviewed acceptance tests, GPT-6.1 Sol High and Claude subscription review.

The task preserves structured field metadata and detaches provenance so source mutation cannot rewrite a returned Context Pack. It uses actual committed files, never a substituted broken fixture. Source inspection checks every registered file against Git HEAD and running bootCommit, mode, regular-file identity, dirty state and sensitive-content rules. Protected tests and source hashes form the sealed one-use approval. Browser/model input cannot supply paths, commands, credentials or a different project.

Codex produces text replacements. Original and candidate packages run in fresh offline Windows Sandboxes with the existing ten boundary canaries. Every registered source must change; expected test counts and High effort are checked before Claude review. Nothing is automatically adopted. Independent adoption approval binds the complete source set, original work and isolated receipt. Adoption retests in another offline Sandbox, commits the complete set once and verifies the exact running version and file hashes. UAC remains Owner-operated.

Rollback needs a fresh approval and matching current files. It restores the complete original set and verifies its recorded original pass/fail counts. Repository writes preserve unrelated staged/unstaged/untracked changes. Proven precommit failures restore only this transaction's unchanged writes; concurrent/ambiguous outcomes stop for inspection, without resetting HEAD. Startup never silently repeats application.

Other projects, arbitrary paths, dependency installs, networked execution, general chat task intake, remote pushes and automatic adoption remain unconnected. Memory final acceptance remains paused; ordinary governed event receipts continue. Acceptance evidence is retained outside the repository in the local development outputs.
