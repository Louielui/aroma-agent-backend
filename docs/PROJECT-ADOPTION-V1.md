# Owner-reviewed local adoption v1

The completed project work order remains immutable evidence. An independent
`project_adoption` record binds its reviewed patch, the independent isolated-coding
receipt, current backend HEAD/bootCommit, exact source bytes, protected eight tests,
action and one-use Owner approval. The registered scope is only
`src/context/contextResult.js` in the local Xiangxiang backend.

Before commit, reread evidence and current source, run the protected tests in a
fresh offline Windows Sandbox, recheck source and authorization, and durably record
write authorization. `git commit --only` commits only the registered file; unrelated
staged, unstaged and untracked changes stay unchanged. No model-selected command,
path, project, remote push or business-data write is supported.

After commit, the record is `awaiting_restart`. The fixed reload helper requests
Owner-operated Windows UAC, restarts only AromaXiangXiangBackend and reloads the
existing supervised Owner bridge. The application reconciles completion read-only
only when HEAD, scoped working bytes and `/health` bootCommit all match the commit.
Declined or failed elevation leaves a retryable reload, never another application.

Rollback needs a separate current-source approval and fresh isolated test run. It
commits only the registered file back to its original bytes, including the five
known snapshot-test failures in that original revision. It does not reset the
repository. A proven uncommitted failure restores only our own bytes; ambiguous
commit outcomes or concurrent edits require inspection rather than automatic reset.

Pending approvals and active pre-commit jobs become interrupted on bridge restart,
with no automatic resume. Awaiting-restart records may be verified on read, but do
not automatically write, commit or relaunch elevation. Owner-only, same-origin API
and `/project-work` page retain separate work, application and rollback history.

Connection status: partial. Only one registered backend repair and local adoption
are integrated. Arbitrary projects, automatic adoption, dependency installation,
remote release and production business-data writes remain unconnected. Memory
acceptance remains paused by Owner; this chapter does not resume indexing or alter
backup schedules.
