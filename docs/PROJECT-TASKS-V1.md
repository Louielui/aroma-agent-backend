# Project task registration v1

Owner scope: local Xiangxiang backend Context module only. Memory completion acceptance remains paused. Production systems, remote push, email, dependency installation and paid API fallback remain unavailable.

`/project-tasks` accepts a natural-language goal, separate acceptance criteria and an editable subset of `src/context/contextResult.js` / `src/context/toolGateway.js`. The other Context file is a read-only dependency. Project root, execution commands, protected test path, providers and reasoning effort are host-owned.

Sol 6.1 High drafts tests through the subscription text-only provider. Source is committed, clean within the profile and identical to `/health bootCommit`. Test code is compiled for syntax without executing on the host. Claude independently reviews the test draft against the Owner criteria and source. Drafts have no execution authority and no claim that tests passed.

Owner approval binds definition, criteria, revision, source snapshot, protected test bytes, expected test count and review into a hash and one-use session nonce. Only approved durable records enter the injected project recipe registry. Restart interrupts active drafts and invalidates pending approvals; approved definitions persist without automatic work. Source drift requires a fresh registration.

Preparing work is a separate operation. Coding approval is independently issued by the existing project-work workflow. Windows Sandbox verifies actual offline baseline failures and candidate results with ten OS boundaries. Coding cannot change protected tests or read-only dependencies. Claude then reviews the implementation. A green baseline or mismatched test count fails rather than fabricating an error.

Adoption still requires its own approval, a fresh offline retest, source and outside-scope verification, one local commit and verified service boot. Rollback requires a separate approval and restores measured original behavior. The administrator reload helper accepts only the closed Context paths and validates the registered definition through committed host code.

All mutations persist their intent before authority or model dispatch. Duplicate starts return the original run without another nonce. Uncertain work preparation never automatically retries. Cancellation and timeout keep the provider lane busy until pending work settles. UI refresh performs reads only and does not retry POSTs.

Limits: no arbitrary project registration, new files, wider file sets, interactive computer control, installed dependencies or autonomous adoption. Task test drafts require explicit human review; schema validity alone cannot prove their semantic adequacy. Acceptance receipts distinguish draft review, actual baseline and candidate execution, implementation review, commit and reload.
