# Chat task planning v1

The current Owner message can prepare the registered Live Context query scope
snapshot task: `香香，修正 Live Context 查詢範圍快照` or
`Fix Xiangxiang Live Context query scope snapshot`. Broad requests ask for scope.
History, retrieved instructions, model output, browser paths and commands do not
select work or authorize it. Additional authority fields are rejected.

The backend binds preparation to its boot commit. The bridge reads both current,
committed, clean registered source files and seals their hashes, the immutable
goal and eight protected acceptance tests. Preparation starts no worker.

Chat displays the work order, source evidence, subscription cost/availability
risk and separate approval controls. Explicit approval uses the existing
one-use, expiring bridge ticket. Sol 6.1 High develops in isolation, the real
offline Windows Sandbox proves baseline and candidate, and Claude reviews via
subscription. Progress, failure reasons, changes and test/review evidence are
read back into the same chat card. There is no automatic mutation retry.

Only a validated result can prepare a separate adoption ticket. Chat shows its
before/after set, current revision and evidence before approval. Adoption repeats
offline acceptance, creates one scoped local commit, invokes the fixed UAC
loader and verifies the new boot. UAC remains Owner-operated.

Conversation history stores a validated run reference, never a nonce or approval.
Reopening chat reads current work and adoption records. Expired/missing tickets
are not reissued from history; cancel and explicitly prepare a new order.
Duplicate preparation keys never reproduce a ticket or transcript. Within a
process, another message/conversation using that key conflicts; uncertain calls
are retained for inspection. A restart invalidates pending bridge approvals.

Connected scope: registered Xiangxiang backend tasks. Other projects, arbitrary
file selection, open-ended planning, dependency installation, automatic adoption,
remote push and production business writes remain unconnected. Memory final
acceptance remains paused; this delivery does not restart indexing or automation.

Acceptance evidence is retained in the calling workspace outputs, including
real natural-language intake, source-bound work, offline tests, Claude review,
separate adoption/reload, full suite and preservation checks. DOM behavior is
tested without controlling the Owner's screen.
