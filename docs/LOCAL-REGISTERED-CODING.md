# Registered local Node repair

This candidate extends Project Tasks and Project Work, not a second queue or a
general host shell. Runtime installation and model allowance are separate Owner
decisions. No existing acceptance ledger is resumed, reset, extended or migrated.

## Entry and approvals

- `/project-tasks` offers local Qwen3.5 9B or the existing separately approved
  Codex/Claude subscription lane. The engine is part of the request dedup key,
  source material, registration hash and coding approval. An existing request
  cannot change its engine. Local work never creates a fake Codex App thread.
- Current Owner commands `local Node repair: <goal>` or `本機修正，<goal>` only
  register an inert request. Quoted material, history and model output cannot
  authorize work. Other wording can use the existing form. This is a bounded
  command entry, not a claim of unrestricted natural-language dispatch.
- Select the exact committed source and explicit criteria; approve the sealed
  source and call limit. Then independently approve the reviewed protected tests
  and the exact coding version. Registration, status and continuation do not
  generate text. Review requests use fresh calls to the same local model, not an
  independently trained model or a guarantee that all defects will be found.
- Test-draft review is a separate stage from final code review. The proposed
  protected tests are line-numbered targets; unchanged source is explicitly
  baseline reference expected to fail new behavior. Local drafting now receives
  a criterion checklist and fixed declared test count, keeps baseline regressions
  distinct, and copies Owner literal examples rather than inventing conversions.
  Each criterion and its semicolon/newline sub-checks need a coverage assessment.
  The host supplies immutable anchor IDs bound to work order, goal, source,
  criteria and complete test bytes. Models select IDs, not retyped quotes or
  guessed line numbers; receipts resolve exact original lines without fuzzy repair.
  Covered criteria must cite executable assert.method lines with selected source
  subjects, including explicitly named CommonJS exports. Titles, comments,
  imports and unrelated source calls cannot satisfy that binding.
  Host validation rejects missing, duplicate or fabricated anchors and incomplete
  pass receipts. It never changes a negative verdict into approval. A grounded
  but semantically mistaken review can still fail; actual model improvement
  requires a separately authorized live acceptance, not offline response doubles.
- This lexical index is deliberately bounded to direct `assert` calls and
  selected relative CommonJS imports. It is not an AST, an evaluator, proof that
  a branch runs, or a semantic oracle for every expected value. Ambiguous slash
  tails and template tails are not indexed. Unsupported indirect/helper styles
  can fail visibly rather than being guessed. A schema-valid coverage reason can
  still be wrong; actual protected assertions and Sandbox results must be reviewed.
  The saved PR173 acceptance generated five mixed tests, omitted stock checks and
  supplied incorrect expected values; its review had wrong whitespace/line anchors
  and title-only coverage. That failure and its two-call paused ledger remain
  immutable. Offline fixture replays validate the new contract, not model learning.
  The PR175 native acceptance generated three tests, then stopped during review
  with `local_output_limit` after two local sends. Its paused root and unused six
  calls are retained. No review verdict, coding candidate or Sandbox result was
  obtained. The failed final model metadata was not recorded, so the historical
  exact limit branch cannot be inferred from the shared error code.
- Draft review now uses `host_anchor_compact_v2` on the wire: short packet-local
  integers plus a required full SHA256 of the complete canonical review packet.
  Full source/test lines, criterion text, every sub-check and explicit criterion
  statuses remain. The model assesses each sub-check once; the host unions its
  references for criterion subject validation and restores the original immutable
  anchor, exact quote and line before applying the existing validator. Missing,
  duplicate, forged, unrelated and stale evidence still fails closed. Compact
  negative/uncertain judgments cannot become approval. The canonical receipt
  retains both wire protocol and version binding. This is an offline format repair,
  not a new native-model judgment or a semantic completeness guarantee.
- Only `.js`, `.cjs` and `.json` under the existing backend source inventory are
  eligible, excluding browser/design assets. Existing three-editable-file limit
  remains. Local packages have at most ten source files and 24 KB including tests.
  No installation, arbitrary command, another repository or business writes.

## Execution and accounting

The reviewed deployment profile selects `registered_node_v1`, honoring an explicit
`XIANGXIANG_LOCAL_CODING=off`. It only connects the provider. Each new scope needs
its own Owner grant; installation creates no usage allowance. Qwen model, digest,
65,536 context and literal-loopback endpoint are pinned by the same deployment
profile as local chat. The current effective reasoning setting is `auto` with
`think:false`; selection and timings are retained in native receipts. Output is
bounded to 4,096 tokens per call, so oversized replacements fail visibly rather
than switching providers or silently truncating accepted code.

The existing durable UsageBudget owns one eight-call limit per registered work,
including test drafting, fresh test review, coding, measured assertion repairs and
result review. It expires after 30 minutes. Website, learning, external dispatch,
unknown phases, wrong digest and cloud models are refused before inference. There
is no local extension or recovery quota path. Restart, concurrent requests and
child work share the same persisted count; unresolved sends block continuation.
Terminal work pauses the root and retains failures and unused capacity.
Failed local sends now retain a bounded diagnostic through the same allowance
evidence store: token-versus-byte limit branch, observed output bytes/hash, safe
final token counts and timings when available. Failure text, HTTP bodies and
arbitrary provider errors are not copied into that diagnostic. Missing terminal
metadata stays null. The 4,096-token and 262,144-byte output limits remain; a
diagnostic persistence failure settles the attempt as failed and blocks success.
Neither output truncation nor a diagnostic error starts another model call.

Only the shared Windows Sandbox executor runs generated tests/code. Baseline must
fail genuinely, accepted tests must pass without skips and the existing source,
protected-test, dependency and hash guards remain active. Only a measured complete
assertion failure permits the existing one coding repair within the same cap.
Transport, scope or audit failures never trigger automatic replay. Local events
stay in the canonical work store and do not enqueue unmetered automatic memory.

Results remain `owner_deployment_package_required`, with source/patch hashes,
RED/GREEN evidence, model/billing/digest, progress and review accessible through
the existing work pages. No automatic adoption, PR merge or production apply.

## Evidence and limits

Source approval now records finite rejection reasons and host-side handler receipt,
evaluation and sealed expiry times in the existing task audit. This distinguishes
arrival after expiry from expiry during source verification; it does not measure
the Owner's click or requests rejected before the handler. Existing historical
`approval_unavailable` failures without these receipts remain undiagnosed.
The source card shows a host-bound Winnipeg deadline/countdown, disables expiry
or unverifiable timing, preserves unchecked confirmation on reload, and reads the
persisted decision after submission. Metadata polling cannot renew or authorize;
an uncertain send is not automatically replayed. The UI disables a refused card;
explicit fresh scope preparation preserves old audit steps. Existing server-side
nonce consumption rules are unchanged: a wrong displayed hash does not consume
the valid nonce. No quota or model dispatch starts from a refusal.
Offline browser and regression tests cover these diagnostics. They do not prove
that the former native approval failure has been reproduced or repaired live.

The earlier two synthetic tasks used two real Qwen calls total and real offline
OS Sandbox RED/GREEN runs. Additional boundary execution found four failures in
the whole-box candidate: invalid pack types, decimal ceiling and unsafe counts.
The corrected example uses exact canonical decimal arithmetic and rejects
unrepresentable counts; duration formatting preserves nonnegative safe integers.
The corrected Sandbox packs pass 11 and 8 tests. Original artifacts are immutable;
corrected copies and hashes are retained separately.

Composition tests use fake HTTP streams and a fake executor to exercise the real
adapter, approvals and budget without new inference. Browser tests inspect both
engine selections, unchecked approval and reload preservation. They do not prove
formal service availability, general programming intelligence or physical-host
air-gap operation. A live registered-work acceptance requires a separate bounded
Owner decision after deployment. Local service, model and Sandbox must already
be installed; no network package download is attempted offline.

## Deployment and recovery

Deploy only the exact final reviewed integration SHA using the established
scope/Hold/promotion gates and fresh backup/isolated-restore evidence. Preserve
launcher and memory settings; no database schema, credential or ACL change.
Verify service/Bridge/client trees, authentication, local coding metadata and
inert per-work budgets with zero model calls before requesting live acceptance.

On version drift, failed gate, missing model/Sandbox, changed old ledgers, cloud
egress or inconsistent source evidence, stop and retain records. Do not replay
spent grants. A same-local-mode exact-source conditional rollback needs its
explicit package authority; reverting to a cloud-enabled version needs a separate
Owner decision. Never restore over formal memory or erase work history.
