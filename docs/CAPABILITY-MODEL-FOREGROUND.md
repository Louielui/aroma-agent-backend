## Observed failure and correction

The final model prompt contained the complete current configuration/work source
lines. Its directAnswer still listed roles and occupancy. The existing validator
successfully bound three requested workflow fields to source-owned model values,
but the compact renderer used directAnswer alone. The correct values were hidden
behind two investigation disclosures. The final route/evidence guard did not
change the answer; disabling that guard would not repair this failure.

The existing validator now carries source identity and role for each accepted
workflow-model fact that survives its final validated sections. It deduplicates
only the same source/role binding. The existing compact capability presentation
uses those accepted model/role values on the face, rather than trusting a
role-only model opening to include them. It retains the full validated report in
the existing investigation details. No question-string exception or extra model
invocation selects this behavior.

Unrecorded configured models are stated as unknown. The fixed daily procurement
background schedule is explicitly separate from dispatchable AI. These notes are
projected only from the same trusted cited work rows; they do not borrow a model,
assume a permission, or claim a tested Worker connection. Ambiguous identities,
untrusted rows, invalid model identifiers and rejected sections cannot supply the
foreground. Other answer kinds and callers without a guaranteed disclosure keep
their existing paths. Read/route guards, omissions and settled required gaps
remain in force.

The existing final-answer contract also asks the model to name relevant recorded
models, associate roles, and distinguish schedules. This prompt improvement is
not the enforcement boundary; the saved bad output is replayed unchanged through
the validator and renderer tests.
