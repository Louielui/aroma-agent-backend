# Registered work purpose and results v1

On-demand, read-only continuation of Investigation Intelligence. No Action
Gateway, scheduler controls, new permissions, inference retries or model changes.

## Connected

- Existing backend runtime reader attaches permission-checked mail thread counts,
  canonical general-memory counters and local capture-outbox counts. Mail access
  is checked before and after reads. Content, accounts and credentials are omitted.
- Closed component purposes describe email analysis, memory capture, indexing and
  consolidation. Originating Owner request links remain UNKNOWN.
- Email counts refer to captured threads, not individual messages or the whole
  mailbox. Failed is a subset of pending. Sync pagination cannot establish missing
  mailbox counts. Missing checkpoint pagination remains unknown.
- Indexing distinguishes saved, raw-only, source-only, pending and unconfirmed.
  These are recorded canonical states, not a fresh remote-index integrity check.
- Consolidation uses the worker's eligible-record predicate; done, empty, pending,
  running, failed and unknown states stay separate. Current candidate count is
  not lifetime output and does not establish approval. Saved running state is
  not live process activity. Outbox counts are current backlog, not lifetime saves.
- Historical host outcomes associate only through existing exact work/run IDs.
  Conflicting outcomes are withheld. Bounded run samples never alter queue totals.
- Same-time conflicting counters are CONTRADICTED. Invalid and snapshots older
  than five minutes are UNKNOWN; inaccessible sources are UNAVAILABLE, never zero.
- Chinese and English intake share the same purpose/progress projection, saved
  references and read-only recommendations, without extra model calls or dispatch.
- The existing Owner-gated read-only context inspection route uses the same live
  backend reader as intake, so live counters can be inspected without a chat call.

## Not connected

Owner-intent provenance, full mailbox inventory/backlog, remote index read-back,
arbitrary-domain outcome adapters, business usefulness, savings predictions,
account-wide usage totals and actual charge attribution. Mail indexing has no new
count projection in this slice. No management authority is added.

## Acceptance

Service fixtures prohibit network, provider/model and write calls; verify source
revocation and private-field exclusion. Tests cover zero/invalid/stale/conflicting
counts, differing historical observations, exact-run deduplication, bilingual
intake with unchanged call count, and the read-only context route. Delivery also
checks real canonical counters through the loaded authenticated HTTP path,
service bootCommit, unchanged brain settings and architecture checklist.
