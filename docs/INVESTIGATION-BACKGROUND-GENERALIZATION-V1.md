# Background investigation generalization v1

This extends the existing read-only investigation sources. It adds no Action
Gateway, management permission, background model calls, model routing changes or
runtime brain changes. Chinese and English use the same judged source policy.

## Separate assertions

- Backend component enablement is distinct from its process activity. Disabled
  does not mean a currently executing operation has stopped; idle is not disabled.
- Bridge configuration is retained independently from the selected in-flight
  request model. Other components join only the unique configured memory route,
  never the model of a possibly unrelated active request. This is configuration
  evidence, not proof that any component has completed a model call.
- Historical successful model results are identified by their invocation receipt
  and memory-completion lane. They do not establish a particular email, component
  or schedule caused that call. Historical running states never prove activity now.
- Observed activity and live-process configuration require valid timestamps within
  the existing five-minute receipt window. Failed/unconnected component reads stay
  UNAVAILABLE; absent values and stale observations stay UNKNOWN. The semantic
  claim binder and fixed bilingual summaries respect these grades.
- Same-time opposing observations remain conflicts. Dated changes are retained as
  transitions; current activity uses the latest independent observation, not the
  first historical value. Ambiguous inventory identities are not selected.

## Acceptance

The live baseline questions are the Chinese and English equivalents of:
"What background jobs exist now, which model does each use, and which are
actually running?" The baseline already routed configuration, schedules,
execution and work independently of Memory. Its missing enablement display and
undifferentiated bridge configuration were the targeted gaps.

Tests exercise a real bridge HTTP read during a controlled pending model request,
the actual operations read adapter with unavailable runtime sources and successful
independent execution reads, bilingual presentation, historical/current separation,
stale and unavailable evidence, malformed booleans and conflicting observations.
Test data is isolated and never rewrites operational history. Real loaded-service
enquiry results and saved receipts are verified separately during delivery.

## Remaining coverage

Only registered backend components, bridge lanes, bounded work records, explicitly
configured Codex automations and the fixed Windows recall task are covered.
External worker inventory and provider billing are incomplete. A source failure
is not evidence of absence. No schedule is paused, worker stopped, setting changed
or external management action performed by these enquiries.
